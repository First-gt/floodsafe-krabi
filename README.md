# FloodSafe Krabi — AI นำทางหลบน้ำท่วม & ศูนย์ประสานงานกู้ภัย

Next.js (App Router) · Tailwind CSS · Lucide · MapLibre GL — มีข้อมูลจำลองของ อ.เมืองกระบี่ อ่าวลึก ปลายพระยา คลองท่อม
พร้อมใช้งานทันที (ไม่ต้องมี API key)

```bash
npm install
npm run dev      # http://localhost:3000
```

## หน้าจอ

| Route | ฟีเจอร์ |
|---|---|
| `/` (ประชาชน) | ระบุข้อมูลรถ → เปิดตำแหน่ง → แตะแผนที่ปักหมุดปลายทาง → AI เลือกเส้นทางที่รถคันนี้ลุยน้ำผ่านได้ · แจ้งน้ำท่วม/ขอความช่วยเหลือ (ทุกช่องบังคับ + ตรวจสอบรูปถ่าย) |
| `/dashboard` (ศูนย์ประสานงาน) | รายการเหตุ (รอ / ส่งทีมแล้ว / ช่วยแล้ว) + แผนที่ · คำแนะนำทรัพยากรจาก AI · จัดทีม/อุปกรณ์ · แสดงสถานะการตรวจรูปถ่าย |

## AI นำทางตามรถ

1. ผู้ใช้ระบุ **ประเภท/รุ่นรถ** และความสูงน้ำสูงสุดที่ลุยได้ (`lib/vehicle.ts`) — AI เดาประเภทรถจากชื่อรุ่นให้
2. ต้อง **เปิดตำแหน่ง** ก่อน (หรือเลือก "ตำแหน่งสาธิต" ถ้าทดสอบนอกจังหวัดกระบี่)
3. แตะบนแผนที่เพื่อ **ปักหมุดปลายทาง** (หรือค้นหาสถานที่ / ศูนย์พักพิงที่ใกล้ที่สุด)
4. `lib/smart-route.ts` ขอเส้นทางถนนจริงหลายตัวเลือกจาก OSRM แล้ว
   - ตรวจแต่ละเส้นกับ **รายงานระดับน้ำจากประชาชน** (`lib/route-eval.ts`)
   - เส้นที่มีจุดน้ำสูงกว่าที่รถลุยได้ = ถูกปฏิเสธ
   - ถ้าทุกเส้นหลักผ่านไม่ได้ จะลองเส้นทางอ้อมผ่านจุดแวะด้านข้าง
   - ถ้าไม่มีทางไป จะบอกตรง ๆ พร้อมเส้นที่น้ำน้อยที่สุด และปุ่มขอความช่วยเหลือ
   - แสดง "AI อธิบายการตัดสินใจ" และรายการรายงานน้ำท่วมบนเส้นทาง
5. ออฟไลน์/OSRM ใช้ไม่ได้ → ใช้กราฟถนนสำรอง (`lib/routing.ts`)
6. ปุ่ม "เริ่มนำทาง" แสดงคำสั่งเลี้ยวทีละจุด และคำนวณใหม่เมื่อออกนอกเส้นทาง

## การตรวจสอบรูปถ่าย (`lib/photo-verify.ts`)

รูปที่แนบต้องผ่านการตรวจก่อนส่งรายงาน:

| การตรวจ | รายละเอียด |
|---|---|
| คุณภาพภาพ | ความละเอียด · ความสว่าง · ความคมชัด |
| EXIF | เวลาถ่าย (ต้องเป็นเหตุการณ์ปัจจุบัน) · พิกัด GPS (ต้องใกล้จุดที่แจ้ง) – ถ้ามีในรูป |
| รูปซ้ำ | perceptual hash เทียบกับรูปที่เคยส่งในเครื่องนี้ |
| ลักษณะผิวน้ำ | สี/พื้นผิวคล้ายน้ำท่วม (heuristic ในเครื่อง) |
| **AI วิชัน (แนะนำ)** | ถ้าตั้ง `GEMINI_API_KEY` → Gemini ดูรูปจริง ตัดสินว่าเป็นน้ำท่วมหรือไม่ และประเมินระดับน้ำ (`app/api/verify-photo/route.ts`) |

ผลลัพธ์: **ตรวจสอบแล้ว** / **รอเจ้าหน้าที่ยืนยัน** / **ไม่ผ่าน** (รูปที่ไม่ผ่านจะไม่ถูกส่ง)

> ⚠️ ถ้าไม่ตั้ง `GEMINI_API_KEY` ระบบใช้เพียง heuristic ซึ่งแยกรูปที่ "ไม่เกี่ยวกับน้ำ" ได้ระดับหนึ่ง
> แต่ไม่ใช่การยืนยันที่เชื่อถือได้ 100% — สำหรับใช้งานจริงควรเปิด AI วิชัน

### เปิดใช้ AI วิชัน

```bash
copy .env.local.example .env.local   # แล้วใส่ GEMINI_API_KEY (รับฟรีที่ aistudio.google.com)
npm run dev                          # รีสตาร์ต
```

ตำแหน่ง · จุดสังเกต · ระดับน้ำ · รถผ่านได้หรือไม่ · จำนวนคน · สิ่งที่ต้องการ (หรือ "ไม่ต้องการ") ·
อันตราย (หรือ "ไม่มี") · รูปถ่ายที่ผ่านการตรวจ · ชื่อ · เบอร์โทร (9–10 หลัก) · รายละเอียด
— มีตัวนับความคืบหน้า แจ้งช่องที่ขาดเป็นสีแดง และเลื่อนไปยังช่องแรกที่ยังไม่กรอก

## แผนที่ & API

- แผนที่พื้นหลัง: OpenFreeMap vector style "Liberty" (ฟรี คมทุกระดับซูม หน้าตาใกล้เคียง Google Maps) - ใส่ `NEXT_PUBLIC_MAPTILER_KEY` เพื่อใช้ MapTiler Streets แทน; ถ้าโหลดไม่ได้จะ fallback เป็น OpenStreetMap raster (ใช้ tile ของ Google Maps กับ MapLibre ไม่ได้ เพราะผิดข้อกำหนดและต้องมี key)
- เส้นทาง: OSRM (`NEXT_PUBLIC_OSRM_URL`, ค่าเริ่มต้นเป็นเซิร์ฟเวอร์สาธิตสาธารณะ — ใช้งานจริงควรตั้งเอง)
- ดูตัวอย่างใน `.env.local.example`

```
lib/road-network.ts     กราฟถนน + เรขาคณิตถนนจริง (road-geometry.json)

lib/mock-data.ts        ข้อมูลจำลอง
```

## ขั้นต่อไปสำหรับใช้งานจริง

- เปลี่ยน `FLOOD_ZONES` เป็น GeoJSON น้ำท่วมจาก Sentinel-1 / GISTDA
- เก็บรายงานลงฐานข้อมูล + realtime (WebSocket / Supabase / Firebase) แทนข้อมูลจำลองใน `lib/store.tsx`
- ตั้งเซิร์ฟเวอร์ OSRM ของตัวเอง และเก็บรูปไว้ใน object storage

## ส่งต่อเคสให้หน่วยงานช่วยเหลือ (เว็บเป็นสื่อกลาง)

- ในเคสที่แจ้งแล้ว (หน้าสรุปหลังแจ้งเหตุ และในแดชบอร์ด) กด "ส่งต่อ/เลือกหน่วยงาน" ระบบจะ:
  1. สรุปเคส (พิกัด ลิงก์แผนที่ ระดับน้ำ จำนวนคน สิ่งที่ต้องการ อุปกรณ์ที่ AI แนะนำ) เป็นข้อความพร้อมส่ง
  2. จัดอันดับหน่วยงานที่เหมาะกับเคส (ทักษะ + พื้นที่ + ความเร่งด่วน) จาก lib/agencies.ts
  3. ให้เลือกช่องทาง: โทร / LINE / อีเมล / คัดลอก / ส่งผ่านระบบ แล้วติดตามสถานะ (ส่งต่อแล้ว → รับเรื่อง → กำลังเดินทาง → เสร็จสิ้น)
- ปุ่มโทรศัพท์บนแผนที่เปิดรายการสายด่วนจริง: **1784** (ปภ.), **1669** (การแพทย์ฉุกเฉิน), **191** (ตำรวจ), **1155** (ตำรวจท่องเที่ยว)
- หน่วยงานที่ติดป้าย "ตัวอย่าง" (ศูนย์ ปภ. จังหวัด, อปท., มูลนิธิ, อาสาเรือ) **ยังไม่ใช่ข้อมูลจริง** ให้แก้ชื่อ/เบอร์ใน lib/agencies.ts ก่อนใช้งานจริง
- "ส่งผ่านระบบ" ต้องตั้งค่า FORWARD_WEBHOOK_URL หรือ RESEND_API_KEY + FORWARD_EMAIL_TO ใน .env.local (ดู .env.local.example) — ถ้าไม่ตั้ง ปุ่มจะถูกปิดและระบบแจ้งตามจริง
- ข้อจำกัด: โทร/LINE/อีเมลเป็นการเปิดแอปในเครื่องผู้ใช้ ระบบไม่รู้ว่าหน่วยงานรับเรื่องแล้วหรือไม่ ผู้ใช้ต้องอัปเดตสถานะเอง (ถ้าต้องการสถานะอัตโนมัติ ต้องมีหน่วยงานเชื่อมต่อ API กลับมา)
